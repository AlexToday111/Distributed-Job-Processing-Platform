# ADR-003: ограниченные исполнители и отмена по токену

Статус: принято.

Проблема: неограниченные горутины и очереди расходуют память, а старая попытка не должна влиять на новую попытку того же задания.

Варианты: отдельная горутина на каждое задание плохо ограничивает ресурсы. Фиксированный пул с общей изменяемой очередью требует дополнительной координации. Фиксированный пул с ограниченным каналом явно передаёт владение заданием и обеспечивает естественное обратное давление.

Решение: N горутин выполнения, канал на Q элементов, защищённое мьютексом отображение активных контекстов по токенам и атомарные флаги готовности. Задание остаётся активным до подтверждённой записи результата. PostgreSQL независимо ограничивает число незавершённых назначений значением N+Q.

Последствия: обработчики должны учитывать контексты. RUNNING включает задания в локальной очереди; тайм-аут обработчика начинается при выполнении, а длительность попытки для аудита — при назначении. Отклонённые аренды адресуются токенами, а не идентификаторами заданий: устаревший ответ heartbeat не может отменить новую попытку.
