# Наблюдаемость

Prometheus опрашивает API, планировщик и двух демонстрационных исполнителей каждые пять секунд. Метрики принадлежат отдельным процессам и сбрасываются при перезапуске. `jobs_*_total` считают события жизненного цикла, наблюдаемые ответственным процессом: API создаёт и отменяет задания, планировщик начинает и завершает попытки, назначает повторы и переводит в DLQ. Повторное подтверждение результата не учитывается дважды. Сбой между фиксацией в БД и обновлением метрики может потерять увеличение счётчика; источником истины остаются таблицы заданий и попыток. Счётчики heartbeat существуют у отправителя и получателя: выбирайте одну роль, а не суммируйте обе.

`jobs{status=...}`, `jobs_ready`, `jobs_running`, `jobs_retry_wait` и показатели работоспособности исполнителей отражают снимок БД, обновляемый планировщиком. При нескольких планировщиках используйте **max**, а не сумму, для этих глобальных показателей. `worker_active_jobs` включает задания в очереди и результаты, ожидающие подтверждения. `scheduler_claimed_jobs_total` и гистограмма длительности получения измеряют транзакции выдачи. Идентификаторы запросов, исполнителей и заданий присутствуют в логах и трассах, но не в метках метрик. Неизвестные HTTP-пути получают общую метку `unmatched`.

Grafana автоматически настраивает графики длины очереди, загрузки исполнителей, частоты завершений, p95 ожидания и выполнения, состояния heartbeat, повторов и истёкших аренд, задержек HTTP и ошибок gRPC. Метки целей опроса Prometheus различают процессы, не создавая отдельные серии для каждого задания. При добавлении постоянных исполнителей обновляйте список целей опроса.

Контекст трассировки сохраняется при создании задания в виде W3C `traceparent`/`tracestate`. Планировщик создаёт `job.dispatch` как дочерний участок трассы и передаёт его контекст в protobuf-назначении. Исполнитель извлекает контекст и создаёт `job.execute`, связывая асинхронный жизненный цикл с участками POST и сохранения в БД. Инструментирование клиента и сервера gRPC дополнительно отслеживает каждый транспортный вызов. Отложенное выполнение может появиться намного позже завершения корневого HTTP-участка трассы; это допустимо. Контекст не содержит данные задания.

API принимает X-Request-Id в формате UUID или генерирует новый UUID. Он присутствует в ошибках и JSON-логах. Метаданные задания передают идентификатор запроса создания в выдачу и выполнение. Логи формируются в JSON через slog и по умолчанию не содержат полный payload или результат.

Демонстрационный Jaeger хранит данные в памяти и теряет трассы при перезапуске. Для реального развёртывания настройте выборку трасс и постоянное хранилище. В демонстрации записываются все трассы, поэтому массовые нагрузочные замеры включают затраты трассировки. Метрики являются эксплуатационными методами и доступны без аутентификации внутри частной сети Compose и через локальные опубликованные порты.
