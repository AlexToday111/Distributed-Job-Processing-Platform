# Гарантии надёжности

Задания сохраняются в БД до успешного ответа на создание. Пустые ключи идемпотентности хранятся как NULL, поэтому разные задания без ключей могут сосуществовать. Непустые ключи уникальны в пределах очереди: повторный запрос возвращает исходное задание с HTTP 200, а не создаёт новую строку с HTTP 201.

Короткие транзакции охватывают получение задания с созданием аренды и попытки, завершение задания и попытки, отмену задания и попытки, а также восстановление с назначением повтора. Сетевые RPC не выполняются внутри транзакций. Блокировки строк PostgreSQL последовательно упорядочивают конкурирующие изменения. Блокировка строки исполнителя не позволяет одновременным вызовам планировщиков назначить ему больше заданий, чем разрешено.

Продление аренды требует точного совпадения `(job_id,worker_id,token)`, состояния RUNNING и ещё не наступившего срока истечения. Истёкший токен нельзя восстановить даже до запуска обработки истёкших аренд. Проверки используют часы PostgreSQL; при подтверждении результата время проверяется после получения блокировки строки, а не по часам хоста планировщика. Завершение требует тех же условий владения; уже подтверждённый результат можно безопасно подтвердить повторно. Предыдущий владелец не может подтвердить успешное завершение восстановленной попытки EXPIRED.

Исполнитель повторяет отправку результатов из памяти, а heartbeat поддерживает аренду до подтверждения записи в БД. При перезапуске планировщика исполнители продолжают работу и сохраняют результаты. Если простой превышает срок аренды, восстановление может запустить повторное выполнение. Перезапуск исполнителя теряет работу и результаты в памяти; истёкшие аренды восстанавливаются из PostgreSQL.

В общем случае невозможно гарантировать выполнение ровно один раз между независимыми системами. Если внешнее HTTP-действие завершилось успешно, а процесс погиб до транзакции подтверждения, другой исполнитель повторит его. Защита токенами сохраняет согласованность БД, но не защищает внешнюю систему. Дедуплицируйте внешние действия стабильным ключом бизнес-операции или задания с уникальным ограничением либо идемпотентностью внешнего провайдера. Уникальное создание задания не означает однократное выполнение обработчика.

Задержка повтора равна `min(base * 2^(attempt-1), cap)`, умноженному на случайный коэффициент в диапазоне [0.5,1]. Источник случайности демонстрационного обработчика `unstable` внедряется для детерминированных тестов. Восстановление аренды расходует тот же ограниченный запас попыток, что и ошибка обработчика. Возврат в очередь сохраняет историю для аудита.

Архивирование содержимого заданий и результатов, а также сроки их хранения пока не реализованы. Создавайте резервные копии БД и настраивайте vacuum: история попыток может расти неограниченно. Исполнитель узнаёт об отмене с задержкой; отмена не может отозвать уже выполненные внешние действия.
